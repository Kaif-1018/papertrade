# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

Crypto paper-trading simulator. Users get a virtual USD balance and trade crypto at live Binance prices. The backend ingests Binance's public WebSocket feed, broadcasts ticks to clients, and executes trades with exact decimal math. Portfolio state, trade history and PnL are persisted and consistent.

## Stack

Python 3.12, FastAPI, SQLAlchemy 2.0 (async, asyncpg), Alembic, PostgreSQL 16, Redis 7, PyJWT, pydantic-settings, `websockets`, pytest + pytest-asyncio + httpx, Docker Compose.

## Environment

- Developer machine is **Windows**. Run everything through Docker. Do not write bash-only or PowerShell-only scripts; use `docker compose` commands or a Makefile that calls them.
- Never run Python or Alembic directly on the host.

## Commands

```
docker compose up --build                                  # run the stack
docker compose exec api pytest -q                          # run tests
docker compose exec api alembic upgrade head               # apply migrations
docker compose exec api alembic revision --autogenerate -m "msg"
docker compose exec api alembic downgrade -1
docker compose exec api python -m app.cli create-admin     # seed an admin user
```

## Architecture

Layered: **routers -> services -> repositories**.

```
app/
  main.py            app factory + lifespan (feed task, redis, pubsub listener)
  core/              config, security, database, redis, logging, price_registry
  models/            SQLAlchemy models
  schemas/           pydantic request/response models
  repositories/      DB access only, no business logic
  services/          business logic (auth, trade, portfolio, price_feed, ws_manager, leaderboard)
  routers/           HTTP and WebSocket endpoints, thin
  api/deps.py        get_db, get_current_user, require_role, require_admin
tests/
alembic/
```

Rules:
- Routers contain no business logic and no DB queries.
- Services own transactions and orchestration. Repositories never commit.
- Raise custom exceptions; the global handler returns `{"error": {"code", "message"}}`.

## Non-negotiable rules

### Money and precision
- **Never use `float` for money, quantity or price.** Use `decimal.Decimal` in Python and `Numeric(18, 8)` in Postgres.
- Build Decimals from strings, never from floats. Parse Binance prices from the string field.
- Quantize to 8 decimal places. Round in the platform's favor (`ROUND_DOWN` on credits to the user).
- Serialize Decimals as strings in JSON responses.

### Trades and concurrency
- A trade is **one transaction**: balance change, holding change and trade record commit together or not at all.
- Lock rows with `SELECT ... FOR UPDATE` (`with_for_update()`) in a consistent order: **user row first, then holding row**, to avoid deadlocks.
- Execution price always comes from the in-memory price registry, never from the client. Reject missing or stale prices (older than 10 seconds).
- Trade records are immutable: no update or delete code paths.
- DB CHECK constraints (balance >= 0, quantity >= 0) are a backstop, not a replacement for service-level validation.

### Real-time
- Send WebSocket pushes only **after** the DB transaction commits, and never let a push failure break the HTTP response.
- Always clean up connections on disconnect, including error paths.
- Binance feed must reconnect with exponential backoff and jitter, with a watchdog for silent stalls.

### Auth and security
- JWT claims: `sub`, `role`, `type` (access|refresh), `jti`, `iat`, `exp`.
- Refresh tokens are stored in Redis as `refresh:{user_id}:{jti}` and rotate on every use. A refresh token whose jti is missing from Redis means reuse: revoke all of that user's refresh tokens and return 401.
- Access tokens must not work as refresh tokens and vice versa.
- Generic "invalid credentials" error for wrong email or wrong password.
- Never log tokens, passwords or secrets.

### Database
- Native Postgres enums for `UserRole` and `TradeType`.
- Timezone-aware timestamps (`server_default=func.now()`).
- Relationships use `lazy="raise"` to prevent accidental async lazy loads. Load what you need explicitly.
- Every schema change goes through an Alembic migration. Review autogenerated migrations before committing.

## Code style

- Fully type-annotated, async by default. No blocking calls inside async code.
- Use SQLAlchemy 2.0 typed style (`Mapped[]`, `mapped_column`).
- Small functions, explicit names. Pure functions for algorithms (for example FIFO PnL) so they are testable without a DB.
- Comments explain why, not what.

## Testing

- Every feature ships with tests. Use a separate test database.
- No real network calls in tests: mock Binance with a local `websockets` server or fake messages.
- Concurrency tests (parallel buys/sells via `asyncio.gather`) must pass repeatedly, not just once.
- Test Decimal exactness explicitly, plus rollback on mid-transaction failure.

## Workflow

- Work one planned day/feature at a time. Do not build ahead of the current task.
- Before finishing a task: run the tests, then review your own changes for bugs, race conditions and security issues, and list anything you find.
- Ask before adding a new dependency, changing the schema outside the current task, or deviating from this document.
- Keep `.env.example` and the README in sync with config changes.

## Known design decisions

- Price registry is an in-memory dict updated by the Binance task; each tick is also published to Redis `prices:{symbol}` for broadcasting.
- Leaderboard is computed on demand and cached in Redis for 30 seconds, invalidated after any trade, with a lock to prevent cache stampedes.
- Realised PnL uses FIFO cost basis, implemented as a pure function over chronological trades.
